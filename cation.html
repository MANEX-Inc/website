      For bot builders
      
Add Cation to your bot

      
Cation is a plain HTTP API, so any bot that can send a web request can use it. Your bot's code sends the user's message to Cation and posts the reply back.


      

        

          
1

          
Get a key

          
Sign in above and create your free key. Save it somewhere safe, since it's shown only once.

        

        

          
2

          
Store the key

          
Keep it in an environment variable such as CATION_KEY on the server that runs your bot. Never paste it into code you share.

        

        

          
3

          
Send messages

          
Send a POST request to the endpoint below, and read the reply from choices[0].message.content.

        

      


      

        
Endpoint

        

        
Send the header Authorization: Bearer YOUR_KEY and a JSON body with a messages list. Each item has a role (user or assistant) and content.

      


      

        
Python (requests)

                
import os
import requests

API_KEY = os.environ["CATION_KEY"]  # keep the key in an environment variable
URL = "https://cation-6a.manex-api.workers.dev/v1/chat/completions"

resp = requests.post(
    URL,
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={"messages": [{"role": "user", "content": "Hello, Cation"}]},
    timeout=60,
)
resp.raise_for_status()
print(resp.json()["choices"][0]["message"]["content"])

      


      

        
JavaScript (Node 18+, discord.js example)

                
// Node 18+ (built-in fetch). Works in discord.js, or any Node bot.
const API_KEY = process.env.CATION_KEY;
const URL = "https://cation-6a.manex-api.workers.dev/v1/chat/completions";

async function askCation(messages) {
  const res = await fetch(URL, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${API_KEY}`,
    },
    body: JSON.stringify({ messages }),
  });
  if (!res.ok) throw new Error(`Cation returned ${res.status}`);
  const data = await res.json();
  return data.choices[0].message.content;
}

// Example: reply when someone mentions your bot in Discord
client.on("messageCreate", async (msg) => {
  if (msg.author.bot || !msg.mentions.has(client.user)) return;
  const text = msg.content.replace(/<@!?\d+>/g, "").trim();
  try {
    const reply = await askCation([{ role: "user", content: text }]);
    await msg.reply(reply.slice(0, 2000)); // Discord messages are limited to 2000 characters
  } catch (err) {
    await msg.reply("Cation is unavailable right now. Please try again later.");
  }
});

      

    

  


  

    

      Good to know
      
Bot notes

      

        

          Does Cation remember earlier messages?
          
No. Each request stands alone. To keep a conversation going, your bot must send the recent messages back in the messages list, alternating user and assistant. The API reads the last 30 messages.

        

        

          Can I change its tone?
          
Yes. Add an optional personality field of up to 300 characters, such as "short and friendly". It only changes tone and form. Cation's identity and rules stay the same.

        

        

          What does a reply look like?
          
The reply is JSON in the same shape as common chat APIs. The text is at choices[0].message.content. Replies are capped in length, so long answers may be shorter than you expect.

        

        

          What errors can I get?
          
401 means the key is missing, wrong, or replaced. 429 means the shared daily allowance has run out, so the service will work again tomorrow. Your bot should show a short message in both cases.

        

        

          Can I check my key or see the models?
          
GET /v1/key with your key confirms it's active. GET /v1/models lists the model name to use, which is cation.

        

        

          Should I call it from the browser?
          
No. Anyone could read a key that's in public website code. Call Cation from your own server or bot, and keep the key private.

        

      

    

  




            

                FAQ
                
Questions

                

                    

                        Is it free?
                        
Yes. Each account gets one free key. Everyone shares one daily allowance, so the service can pause when it runs out.

                    

                    

                        Can I have more than one key?
                        
One key per account. You can replace it at any time, and the old key stops working right away.

                    

                    

                        What if I lose my key?
                        
Sign in again and choose Replace my key. Keys are shown only once, so save yours when it appears.

                    

                    

                        What if I lose my device?
                        
A passkey lives on the device where you created it. If you lose that device, you can't sign in with that passkey, and there is no recovery. You can create a new passkey account with a different username.

                    

                    

                        What do you store about me?
                        
Your account ID, your username or GitHub login, and a hash of your key. For passkeys, we store only the public key, which can't sign anyone in by itself. This browser keeps a sign-in token until you sign out.

                    

                    

                        Can I use it in my bot?
                        
Yes. Call the endpoint from your own server or agent, and keep your key private. Don't put it in public website code.
